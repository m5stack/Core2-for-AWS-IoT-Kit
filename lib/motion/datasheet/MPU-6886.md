# MPU-6886 Firmware Implementation Specification

Source: `MPU-6886.pdf`, InvenSense document DS-000193, Revision 1.1.

## 1. Purpose

This document is a self-contained firmware implementation reference for the MPU-6886 6-axis motion sensor. It is intended to enable automatic generation of firmware drivers, HAL layers, BSP support, protocol handlers, and automated tests without requiring the original datasheet. The device combines a 3-axis gyroscope, 3-axis accelerometer, temperature sensor, FIFO, interrupt logic, and I2C/SPI host interfaces 

## 2. Device Overview

The MPU-6886 is a 6-axis MotionTracking device in a 3 mm x 3 mm x 0.75 mm 24-pin LGA package. It integrates:

* 3-axis gyroscope
* 3-axis accelerometer
* on-chip 16-bit ADCs
* programmable digital filters
* digital-output temperature sensor
* 1 kB FIFO
* programmable interrupts
* I2C and SPI slave interfaces

Key operating ranges and capabilities:

* VDD: 1.71 V to 3.45 V
* VDDIO: 1.71 V to 3.45 V
* Gyro full-scale ranges: ±250, ±500, ±1000, ±2000 dps
* Accel full-scale ranges: ±2 g, ±4 g, ±8 g, ±16 g
* I2C up to 400 kHz
* SPI up to 10 MHz
* FIFO size: 1 kB
* Operating temperature: -40 °C to +85 °C
* Shock tolerance: 20,000 g unpowered for 0.2 ms

Internal software-relevant subsystems:

* gyro signal chain
* accel signal chain
* temperature ADC
* digital low-pass filter blocks
* FIFO buffer and count logic
* interrupt generation and status
* wake-on-motion logic
* clock selection / PLL / internal oscillator control
* power management and standby control

## 3. Communication Interfaces

### 3.1 Supported Interfaces

The MPU-6886 exposes:

* I2C slave
* 4-wire SPI slave

Pins:

* Pin 23: SCL / SPC
* Pin 24: SDA / SDI
* Pin 9: SA0 / SDO
* Pin 22: nCS

### 3.2 I2C Interface

The device always operates as an I2C slave.

Addressing:

* 7-bit slave address: `110100X`
* SA0 = 0 → address `0x68`
* SA0 = 1 → address `0x69`

Electrical / bus requirements:

* open-drain SDA/SCL
* pull-ups required, example: 10 kΩ
* max bus speed: 400 kHz
* standard mode supported at 100 kHz

I2C transaction model:

* write: `START + address(W) + register address + data bytes + STOP`
* read: `START + address(W) + register address + REPEATED START + address(R) + data bytes + NACK + STOP`
* multi-byte accesses auto-increment register address

I2C timing requirements:

* fSCL: 100 kHz to 400 kHz
* tHD.STA: 0.6 µs min
* tLOW: 1.3 µs min
* tHIGH: 0.6 µs min
* tSU.STA: 0.6 µs min
* tHD.DAT: 0 µs min
* tSU.DAT: 100 ns min
* rise time: `20 + 0.1*Cb` ns to 300 ns max
* fall time: `20 + 0.1*Cb` ns to 300 ns max
* tSU.STO: 0.6 µs min
* tBUF: 1.3 µs min
* bus capacitance per line: < 400 pF
* tVD.DAT: 0.9 µs max
* tVD.ACK: 0.9 µs max 

### 3.3 SPI Interface

The device always operates as an SPI slave.

Supported modes:

* SPI mode 0
* SPI mode 3

SPI behavior:

* 4-wire
* data MSB first
* data latched on rising edge of SPC
* data changes on falling edge of SPC
* `CS` active low
* non-selected slaves tri-state SDO
* read/write completed in 16 or more clocks
* first byte is address byte:

  * bit7 = R/W
  * bits6:0 = register address
  * R/W = 1 for read
  * R/W = 0 for write
* subsequent bytes are data
* burst read/write supported

SPI timing:

* fSPC: 10 MHz max
* tLOW: 45 ns min
* tHIGH: 45 ns min
* tSU.CS: 2 ns min
* tHD.CS: 63 ns min
* tSU.SDI: 3 ns min
* tHD.SDI: 7 ns min
* tVD.SDO: 40 ns max with 20 pF load
* tDIS.SDO: 20 ns max

At 10 MHz, duty cycle should be 45% to 55%.

Minimum serial clock rate depends on ODR:

* if ODR < 4 kHz: minimum clock 100 kHz
* if ODR > 4 kHz: minimum clock 200 kHz

## 4. Device Addressing and Identification

### 4.1 Bus Address

I2C:

* `0x68` when SA0 low
* `0x69` when SA0 high

SPI:

* no fixed bus address; device selected by nCS

### 4.2 Device Identification

Register:

* `WHO_AM_I` at `0x75`
* reset/default value: `0x19`

This value is the device ID and is distinct from the I2C slave address.

### 4.3 Discovery Procedure

Recommended discovery:

1. Bring supplies within range.
2. Wait for supply ramp to complete.
3. Access interface:

   * I2C at `0x68` or `0x69`, or SPI with nCS asserted.
4. Read `WHO_AM_I` (`0x75`).
5. Verify returned value equals `0x19`.
6. If power-up was performed with SCL/SPC and CS low, issue software reset before initialization.

## 5. Communication Protocol

### 5.1 I2C Register Write Example

Single-byte write to `PWR_MGMT_1` (`0x6B`) with data `0x01`:

`START -> 0x68<<1 | 0 -> ACK -> 0x6B -> ACK -> 0x01 -> ACK -> STOP`

Burst write:

`START -> addr(W) -> ACK -> reg -> ACK -> data0 -> ACK -> data1 -> ACK -> ... -> STOP`

### 5.2 I2C Register Read Example

Read `WHO_AM_I`:

`START -> addr(W) -> ACK -> 0x75 -> ACK -> REPEATED START -> addr(R) -> ACK -> data -> NACK -> STOP`

Burst read:

`START -> addr(W) -> ACK -> start_reg -> ACK -> REPEATED START -> addr(R) -> ACK -> data0 -> ACK -> data1 -> ACK -> ... -> last_data -> NACK -> STOP`

### 5.3 SPI Register Write Example

Write `PWR_MGMT_1` (`0x6B`) = `0x01`:

* first byte = `0b0_1101011` = `0x6B`
* second byte = `0x01`

Transaction:

`CS low -> 0x6B -> 0x01 -> CS high`

### 5.4 SPI Register Read Example

Read `WHO_AM_I` (`0x75`):

* first byte = `0b1_1110101` = `0xF5`
* second byte clocks out data

Transaction:

`CS low -> 0xF5 -> read returned byte -> CS high`

### 5.5 Multi-byte Transfers

* I2C multi-byte accesses auto-increment register address.
* SPI supports burst read and write to consecutive addresses.
* FIFO reads use repeated reads from `FIFO_R_W` (`0x74`).

## 7. Register Bitfields

### 7.1 0x04 XG_OFFS_TC_H

| Bits | Name              | Access | Reset | Description                                                                     |
| ---- | ----------------- | ------ | ----- | ------------------------------------------------------------------------------- |
| 7:2  | XG_OFFS_LP[5:0]   | R/W    | 0     | LP-to-LN gyro offset shift, 2’s complement, 0.125 dps/LSB, +3.875 dps to -4 dps |
| 1:0  | XG_OFFS_TC_H[9:8] | R/W    | 0     | high bits of 10-bit X gyro temperature compensation offset                      |

### 7.2 0x05 XG_OFFS_TC_L

| Bits | Name              | Access | Reset | Description                         |
| ---- | ----------------- | ------ | ----- | ----------------------------------- |
| 7:0  | XG_OFFS_TC_L[7:0] | R/W    | 0     | low bits of 10-bit X gyro TC offset |

Notes for TC registers (`0x04/0x05`, `0x07/0x08`, `0x0A/0x0B`):

* TC always enabled
* effective only when non-zero coefficients programmed at factory
* 10-bit signed magnitude/offset adjustment
* resolution: 2.52 mdps/°C
* writing zero disables temperature compensation effect
* restored by power-up or `DEVICE_RESET`

### 7.3 0x07 / 0x08 Y gyro TC

Same format as X gyro:

* `0x07[7:2]` = `YG_OFFS_LP[5:0]`
* `0x07[1:0]` = `YG_OFFS_TC_H[9:8]`
* `0x08[7:0]` = `YG_OFFS_TC_L[7:0]`

### 7.4 0x0A / 0x0B Z gyro TC

Same format as X gyro:

* `0x0A[7:2]` = `ZG_OFFS_LP[5:0]`
* `0x0A[1:0]` = `ZG_OFFS_TC_H[9:8]`
* `0x0B[7:0]` = `ZG_OFFS_TC_L[7:0]`

### 7.5 0x0D / 0x0E / 0x0F accel self-test codes

| Register | Bits | Name       | Access | Reset | Description                    |
| -------- | ---- | ---------- | ------ | ----- | ------------------------------ |
| 0x0D     | 7:0  | XA_ST_DATA | R/W    | OTP   | factory X accel self-test code |
| 0x0E     | 7:0  | YA_ST_DATA | R/W    | OTP   | factory Y accel self-test code |
| 0x0F     | 7:0  | ZA_ST_DATA | R/W    | OTP   | factory Z accel self-test code |

### 7.6 0x13..0x18 gyro user offsets

Each is R/W, reset `0x00`, signed 16-bit two’s complement offset added to sensor value before data register output.

* `0x13`: X_OFFS_USR[15:8]
* `0x14`: X_OFFS_USR[7:0]
* `0x15`: Y_OFFS_USR[15:8]
* `0x16`: Y_OFFS_USR[7:0]
* `0x17`: Z_OFFS_USR[15:8]
* `0x18`: Z_OFFS_USR[7:0]

### 7.7 0x19 SMPLRT_DIV

| Bits | Name       | Access | Reset | Description                |
| ---- | ---------- | ------ | ----- | -------------------------- |
| 7:0  | SMPLRT_DIV | R/W    | 0     | output sample rate divider |

Effective only when:

* `FCHOICE_B = 00`
* `0 < DLPF_CFG < 7`

Formula:

`SAMPLE_RATE = INTERNAL_SAMPLE_RATE / (1 + SMPLRT_DIV)`

with `INTERNAL_SAMPLE_RATE = 1 kHz`

## 8. Reserved Bit Handling

Rules:

* Reserved bits without explicit meaning must be preserved during read-modify-write.
* When writing registers with reserved bits, write zero to reserved bits unless preserving previous contents is required.
* Do not assume reserved bits read as zero.
* Do not use undocumented registers.
* Do not read unlisted registers in Sleep mode; this may hang the device and require a power cycle.

## 9. Commands or Opcodes

The device is register-based only. It has no separate command opcode table beyond I2C/SPI register access conventions.

SPI address byte:

* bit7 = R/W
* bits6:0 = register address

Pseudo-opcodes:

| Operation | Code Form              | Parameters                   | Description       |
| --------- | ---------------------- | ---------------------------- | ----------------- |
| SPI write | `0AAAAAAA`             | one or more data bytes       | write register(s) |
| SPI read  | `1AAAAAAA`             | clocks out one or more bytes | read register(s)  |
| I2C write | addr+W, RA, data...    | register address and data    | write register(s) |
| I2C read  | addr+W, RA, Sr, addr+R | register address then read   | read register(s)  |

## 10. Data Formats

### 10.1 Byte Order

All multi-byte sensor values are big-endian in register order:

* high byte at lower register address
* low byte at next register address

### 10.2 Numeric Representations

* sensor outputs: signed 16-bit two’s complement
* gyro user offsets: signed 16-bit two’s complement
* gyro TC offsets: signed 10-bit two’s complement
* accel offset cancellation: signed 15-bit value with low-byte bit0 reserved

### 10.3 Gyroscope Output Scaling

Sensitivity:

* FS_SEL=0: 131 LSB/(dps)
* FS_SEL=1: 65.5 LSB/(dps)
* FS_SEL=2: 32.8 LSB/(dps)
* FS_SEL=3: 16.4 LSB/(dps)

Conversion:

`angular_rate_dps = raw_gyro / gyro_sensitivity`

### 10.4 Accelerometer Output Scaling

Sensitivity:

* AFS_SEL=0: 16384 LSB/g
* AFS_SEL=1: 8192 LSB/g
* AFS_SEL=2: 4096 LSB/g
* AFS_SEL=3: 2048 LSB/g

Conversion:

`accel_g = raw_accel / accel_sensitivity`

### 10.5 Temperature Output Scaling

* ADC resolution: 16 bits
* 25 °C output: 0 LSB
* sensitivity: 326.8 LSB/°C
* room temp offset: 25 °C
* room temp offset error: -15 °C to +15 °C

Formula:

`TEMP_degC = (TEMP_OUT[15:0] / 326.8) + 25`

### 10.6 Self-Test OTP Conversion

For accel and gyro self-test codes:

`ST_OTP = (2620 / 2^FS) * 1.01^(ST_code - 1)` in LSB

`ST_code = round( log(ST_FAC / (2620 / 2^FS)) / log(1.01) ) + 1`

## 11. Timing Requirements

### 11.1 Startup and Reset

* Supply ramp time: 0.01 ms to 3 ms, monotonic from 10% to 90%
* Gyroscope startup time: 35 ms typ, 100 ms max from gyro enable to gyro drive ready
* Accelerometer startup time: 10 ms typ, 20 ms max from sleep mode to valid data
* Temperature sensor stabilization time: 14000 µs
* clock transition when gyro turned off: about 20 µs

### 11.2 Output Data Rates

Gyro:

* low-noise mode: 3.91 Hz to 8000 Hz
* low-power mode: 3.91 Hz to 333.33 Hz

Accel:

* low-noise mode: 3.91 Hz to 4000 Hz
* low-power mode: 3.91 Hz to 500 Hz

Temperature:

* no filter: 8000 Hz
* with filter: 3.91 Hz to 1000 Hz

### 11.3 Bus Timing

Use the I2C and SPI timing tables exactly as listed above.

### 11.4 Interrupt Timing

* INT pulse width when `LATCH_INT_EN = 0`: 50 µs

### 11.5 Mode Change Notes

* first output sample in accel-only low-noise mode after wake has 1 ms delay independent of ODR
* changing `SMPLRT_DIV` in accel low-power mode takes effect after up to one sample at old ODR
* switching from low-power to low-noise can produce unsettled output samples
* gyro takes one ODR clock period to switch from low-noise to low-power after `GYRO_CYCLE=1`

Standard power modes:

### 12.1 Entering Sleep

* set `PWR_MGMT_1.SLEEP = 1`

### 12.2 Accel-only Low-Noise

* wake from sleep
* enable accel axes
* disable gyro axes or standby gyro
* configure accel filter and FSR
* note first sample delayed by 1 ms

### 12.3 Accel Low-Power

* gyro disabled
* `CYCLE = 1`

### 12.4 Gyro Low-Power

* set `LP_MODE_CFG.GYRO_CYCLE = 1`
* configure `G_AVGCFG`

### 12.5 Gyro Standby

* `GYRO_STANDBY = 1`
* at least one gyro axis must be on when entering standby

## 13. Reset Behavior

### 13.1 Power-On Reset

* device comes up in sleep mode
* non-exception registers reset to `0x00`
* exceptions:

  * `CONFIG = 0x80`
  * `PWR_MGMT_1 = 0x41`
  * `WHO_AM_I = 0x19`
  * self-test registers contain OTP values

### 13.2 Software Reset

Set:

* `PWR_MGMT_1.DEVICE_RESET = 1`

Behavior:

* internal registers restored to defaults
* bit auto-clears on completion
* TC coefficients reloaded from factory trim

### 13.3 Signal Path Reset

Partial resets:

* `SIGNAL_PATH_RESET.ACCEL_RST`
* `SIGNAL_PATH_RESET.TEMP_RST`

Full signal-path reset:

* `USER_CTRL.SIG_COND_RST = 1`

This clears all sensor registers.

## 15. Interrupts

Interrupt sources:

* Motion Detection
* FIFO Overflow
* Data Ready
* Gyro Drive Ready
* FSYNC interrupt
* FIFO watermark interrupt

Enable registers:

* `INT_ENABLE`
* `INT_PIN_CFG`

Status registers:

* `FSYNC_INT`
* `FIFO_WM_INT_STATUS`
* `INT_STATUS`

Clearing behavior:

* most status bits clear on read of their status register
* `INT_RD_CLEAR=1` allows any read to clear interrupt status
* FIFO watermark is special:

  * cleared on first `FIFO_R_W` read
  * if FIFO count still above threshold after read, watermark reasserts

INT pin behavior:

* polarity selectable via `INT_LEVEL`
* push-pull or open drain via `INT_OPEN`
* pulse or latched via `LATCH_INT_EN`

## 16. Operational Sequences

### 16.1 Basic Initialization Sequence

1. Power supplies within range.
2. Wait for ramp completion.
3. Read `WHO_AM_I`; verify `0x19`.
4. Issue `DEVICE_RESET` if desired or required.
5. Clear `SLEEP`.
6. Set `CLKSEL = 001`.
7. Configure FSR and filters.
8. Configure standby bits for unused axes.
9. Configure FIFO and/or interrupts if used.
10. Wait startup times before trusting outputs.

### 16.2 Start Continuous 6-Axis Sampling

1. `PWR_MGMT_1`: `SLEEP=0`, `CYCLE=0`, `GYRO_STANDBY=0`, `TEMP_DIS=0`, `CLKSEL=001`
2. `PWR_MGMT_2`: clear `STBY_XA/YA/ZA/XG/YG/ZG`
3. Configure:

   * `GYRO_CONFIG.FS_SEL`
   * `ACCEL_CONFIG.ACCEL_FS_SEL`
   * `CONFIG.DLPF_CFG`
   * `GYRO_CONFIG.FCHOICE_B`
   * `ACCEL_CONFIG2.ACCEL_FCHOICE_B`
   * `ACCEL_CONFIG2.A_DLPF_CFG`
   * `SMPLRT_DIV`
4. Wait:

   * gyro startup up to 100 ms
   * accel startup up to 20 ms
5. Read outputs or use DRDY/FIFO.

### 16.3 FIFO Operation

1. Configure source selection in `FIFO_EN`
2. Enable FIFO mode with `USER_CTRL.FIFO_EN = 1`
3. Optionally reset FIFO using `USER_CTRL.FIFO_RST = 1`
4. Optionally set watermark using `FIFO_WM_TH1/TH2`
5. Read `FIFO_COUNTH/L` to determine count
6. Read `FIFO_R_W` repeatedly

### 16.4 Wake-on-Motion

The datasheet sequence:

1. Ensure accelerometer running:

   * `PWR_MGMT_1`: `CYCLE=0`, `SLEEP=0`, `GYRO_STANDBY=0`
   * `PWR_MGMT_2`: accel standby bits = 0, gyro standby bits = 1
2. Set accel LPF bandwidth to 218.1 Hz:

   * `ACCEL_CONFIG2.ACCEL_FCHOICE_B = 0`
   * `ACCEL_CONFIG2.A_DLPF_CFG = 1`
3. Enable motion interrupt:

   * `INT_ENABLE.WOM_X/Y/Z_INT_EN = 1`
4. Set thresholds in `ACCEL_WOM_X/Y/Z_THR`
5. Enable hardware intelligence:

   * `ACCEL_INTEL_CTRL.ACCEL_INTEL_EN = 1`
   * `ACCEL_INTEL_CTRL.ACCEL_INTEL_MODE = 1`
   * ensure bit0 set to 0 for OR mode unless AND mode desired
6. Set wake-up frequency via `SMPLRT_DIV`
7. Enable cycle mode:

   * `PWR_MGMT_1.CYCLE = 1`

## 17. Driver Initialization Sequence

Recommended startup:

1. Bring `VDD` and `VDDIO` into range.
2. Wait for supply ramp completion.
3. Probe interface and read `WHO_AM_I`.
4. If power-up occurred with `SCL/SPC` and `CS` low, issue software reset.
5. Set `PWR_MGMT_1.DEVICE_RESET = 1`, wait for bit clear.
6. Write `PWR_MGMT_1`:

   * `SLEEP = 0`
   * `CLKSEL = 001`
   * keep `TEMP_DIS = 0` unless temperature unused
7. Write `ACCEL_INTEL_CTRL.OUTPUT_LIMIT = 1`
8. Configure axes in `PWR_MGMT_2`
9. Configure filter / FSR / divider registers
10. Wait:

* 20 ms for accel validity
* up to 100 ms if gyro enabled

11. Discard first sample after relevant mode transitions when advised
12. Enable interrupts / FIFO last

## 18. Runtime Operation Sequences

### 18.1 Read 6-Axis Sample

1. Burst read `0x3B..0x48`
2. Parse signed big-endian values
3. Convert using current scale constants

### 18.2 Update Full-Scale Range

1. Read-modify-write `GYRO_CONFIG` or `ACCEL_CONFIG`
2. Preserve reserved bits
3. Update cached driver sensitivity constants
4. Discard transient samples immediately after change

### 18.3 Handle Data Ready Interrupt

1. Read `INT_STATUS`
2. Confirm `DATA_RDY_INT`
3. Burst read sensor registers or FIFO
4. Clear interrupt per configured mode

### 18.4 Handle FIFO Watermark

1. Read FIFO until desired depth reached
2. Be aware first FIFO read clears watermark status
3. Re-check `FIFO_COUNT`
4. If still above threshold, watermark can reassert

### 18.5 Reset FIFO

1. Disable FIFO producer or stop consuming race conditions if needed
2. Set `USER_CTRL.FIFO_RST = 1`
3. Re-enable FIFO sources if required

## 19. Driver State Model

Driver should track at minimum:

* interface type: I2C or SPI
* I2C address or SPI chip select binding
* current gyro FSR
* current accel FSR
* current gyro sensitivity LSB/dps
* current accel sensitivity LSB/g
* current `SMPLRT_DIV`
* current filter configuration
* current power mode
* enabled axes
* FIFO enabled state and selected sources
* interrupt configuration
* whether temp sensor enabled
* whether `CLKSEL` configured correctly
* whether `OUTPUT_LIMIT` has been set to 1 after power-up
* whether startup delays have elapsed
* whether first-sample discard is pending after mode changes

## 20. Required Safety and Correctness Rules for Code Generation

1. Always verify `WHO_AM_I == 0x19` before full initialization.
2. Always set `PWR_MGMT_1.CLKSEL = 001` for full gyroscope performance.
3. Always set `ACCEL_INTEL_CTRL.OUTPUT_LIMIT = 1` after power-up.
4. Preserve reserved bits during read-modify-write.
5. Never read undocumented register locations in Sleep mode.
6. Do not trust gyro output until gyro startup delay has elapsed.
7. Do not trust accel output until accel startup delay has elapsed.
8. Discard unsettled samples after low-power to low-noise transitions.
9. If `GYRO_CYCLE` is set before gyro turn-on, ignore first reading.
10. Use big-endian assembly for all 16-bit sensor values.
11. Apply the correct sensitivity constant for the programmed full-scale range.
12. Use `TEMP_degC = raw/326.8 + 25`.
13. Treat FIFO empty `0xFF` as FIFO-empty indication.
14. Handle FIFO watermark interrupt clearing on first FIFO read.
15. If using watermark interrupt, ensure bit 7 of `CONFIG` (0x1A) — the reserved default-1 bit, which is separate from `FIFO_MODE` (bit 6) — is set to 0 before use.
16. For SPI-only deployments, `I2C_IF_DIS` may be set, but do not do so if fallback I2C access is required.
17. When entering gyro standby, ensure at least one gyro axis is on first.
18. To transition from gyro standby to gyro off:

    * clear `GYRO_STANDBY`
    * then disable gyro axes
19. For temp sensor retention during transition from gyro low-power to standby with accel disabled:

    * set `GYRO_CYCLE = 0` at least one ODR cycle earlier
    * ensure at least one gyro axis is on
    * then set `GYRO_STANDBY = 1`
20. If power-up happened with SCL/SPC and CS low, software reset is required before initialization.

## 24. Minimal Functional Feature Set

A correct minimum driver must support:

1. I2C or SPI register read/write
2. `WHO_AM_I` verification
3. reset and wake from sleep
4. clock configuration to `CLKSEL=001`
5. accel and gyro full-scale configuration
6. sample-rate/divider configuration
7. burst read of accel, gyro, and temperature outputs
8. raw-to-physical unit conversion
9. axis standby and power-state control
10. FIFO enable/read/reset
11. interrupt status read/clear
12. wake-on-motion configuration

## 25. Final Implementation Intent

A generated driver should behave as a robust register-level transport plus stateful sensor-control layer. It should:

* initialize deterministically
* verify device identity
* explicitly manage sleep, standby, and mode transitions
* cache scale settings and convert measurements correctly
* preserve reserved bits
* respect timing and startup delays
* handle FIFO and interrupts correctly, including special watermark semantics
* avoid reading undocumented registers

Common implementation mistakes to avoid:

* forgetting `CLKSEL=001`
* not setting `OUTPUT_LIMIT=1`
* treating `WHO_AM_I` as I2C address
* using wrong byte order
* using wrong sensitivity for selected FSR
* trusting first samples immediately after mode transitions
* mishandling FIFO full/empty behavior
* assuming watermark clears like other interrupts
* reading unlisted registers in sleep mode
* not discarding or re-synchronizing after reset

## 26. Absolute Maximum Ratings

Stress beyond these ratings may cause permanent damage. These are stress
ratings only; functional operation at these conditions is not implied.

| Parameter                                | Rating                  |
| ---------------------------------------- | ----------------------- |
| Supply voltage, VDD                      | -0.5 V to +4 V          |
| Supply voltage, VDDIO                    | -0.5 V to +4 V          |
| REGOUT                                   | -0.5 V to +2 V          |
| Input voltage (SA0, FSYNC, SCL, SDA)     | -0.5 V to VDDIO + 0.5 V |
| Acceleration (any axis, unpowered)       | 20,000 g for 0.2 ms     |
| Operating temperature range              | -40 °C to +85 °C        |
| Storage temperature range                | -40 °C to +125 °C       |
| ESD protection                           | 2 kV (HBM); 250 V (MM)  |
| Latch-up                                 | JEDEC Class II (2), 125 °C, ±100 mA |

Note: REGOUT is the internal LDO output and must be bypassed with a 0.1 µF
capacitor; it must not be driven externally.
