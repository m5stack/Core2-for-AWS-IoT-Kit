# BM8563 Firmware Driver Implementation Specification

Source: `BM8563_cn.pdf`, Belling BM8563 Chinese datasheet V1.1.

## 1. Purpose

This document is a self-contained firmware implementation reference for the BM8563 real-time clock/calendar device. It is intended to support automatic generation of firmware drivers, HAL layers, BSP integrations, communication protocol handling, and automated test logic without requiring any other source material. Device capabilities, register definitions, bitfields, bus protocol behavior, timing limits, reset behavior, and operational sequences are consolidated here from the provided device information.  

## 2. Device Overview

BM8563 is a low-power CMOS real-time clock/calendar with an I2C slave interface, integrated 32.768 kHz oscillator support, programmable clock output, alarm function, countdown timer, interrupt output, and power-loss detection. It tracks seconds, minutes, hours, weekday, day, month, and year, and includes a century flag. Maximum I2C bus speed is 400 kbit/s. Internal register addressing auto-increments after each byte access.  

Relevant software-visible functional subsystems:

* RTC calendar/time counters
* Alarm engine
* Countdown timer
* Programmable CLKOUT generator
* Power-loss indicator
* Interrupt generation logic
* I2C serial interface
* Oscillator and divider chain

Supported supply and operating range:

* VDD operating range with I2C inactive: 1.5 V to 5.5 V
* VDD operating range with I2C active at 400 kHz: 1.8 V to 5.5 V
* Operating temperature: -40 °C to +85 °C  

## 3. Communication Interfaces

### 3.1 Primary Host Interface: I2C

BM8563 is an I2C slave device. All address and data transfers occur through the I2C bus. Maximum bus speed is 400 kHz. After each read or write byte, the internal word-address pointer auto-increments.  

Electrical and timing interface constraints:

* Maximum SCL frequency: 400 kHz
* Start hold time tHD;STA: 0.6 µs min
* Repeated start setup time tSU;STA: 0.6 µs min
* SCL low time tLOW: 1.3 µs min
* SCL high time tHIGH: 0.6 µs min
* SDA/SCL rise time tr: 0.3 µs max
* SDA/SCL fall time tf: 0.3 µs max
* Data setup time tSU;DAT: 100 ns min
* Data hold time tHD;DAT: 0 ns min
* Stop setup time tSU;STO: 0.6 µs min
* Acceptable bus spike width tSW: 50 ns max
* Bus capacitance Cb: 400 pF max
* Time between a START and STOP containing an access must be less than 1 s 

I2C lines:

* SDA: open-drain bidirectional serial data
* SCL: serial clock input
* Both SDA and SCL require pull-up resistors to VDD  

### 3.2 Auxiliary Pins Relevant to Firmware

* `INT`: open-drain interrupt output
* `CLKOUT`: open-drain programmable clock output
* `OSCI`: oscillator input
* `OSCO`: oscillator output 

### 3.3 Multi-byte Behavior

The internal word-address register auto-increments after each byte access. Sequential multi-byte reads or writes can therefore access consecutive registers without re-sending the register address for each byte. 

## 4. Device Addressing and Identification

### 4.1 I2C Slave Address

The device uses a fixed 7-bit slave address of `0b1010001` = `0x51`.

Transferred address bytes:

* Write address byte: `0xA2`
* Read address byte: `0xA3`  

### 4.2 Register Addressing

The internal register space is 16 bytes wide, addressed from `0x00` to `0x0F`. The word address field used on the bus is 8 bits, but only the low 4 bits are meaningful for register selection; the upper 4 bits are unused.  

### 4.3 Identification Registers

No manufacturer ID register, silicon revision register, or explicit device ID register is defined in the provided information.

### 4.4 Discovery Procedure

Recommended discovery:

1. Issue START.
2. Send slave write byte `0xA2`.
3. Verify ACK.
4. Optionally read control/status registers from `0x00` and `0x01`.
5. Optionally verify time registers are readable.
6. Treat lack of ACK as device absent or bus fault.

## 5. Communication Protocol

### 5.1 Basic I2C Behavior

START condition: SDA falling while SCL is high.
STOP condition: SDA rising while SCL is high.
Data must remain stable while SCL is high. One bit is transferred per clock pulse. Every 8-bit byte is followed by an ACK bit.  

### 5.2 Supported Access Patterns

The device supports three access forms.

#### A. Write mode

Sequence:

1. START
2. Slave address + write (`0xA2`)
3. Word address
4. One or more data bytes
5. STOP

The device auto-increments the word address after each data byte. 

#### B. Random read / addressed read

Sequence:

1. START
2. Slave address + write (`0xA2`)
3. Word address
4. Repeated START
5. Slave address + read (`0xA3`)
6. Read one or more data bytes
7. Master ACK after each byte except final byte
8. NACK on last byte
9. STOP 

#### C. Current-address sequential read

Sequence:

1. START
2. Slave address + read (`0xA3`)
3. Read one or more bytes from current internal address
4. Internal address auto-increments
5. NACK final byte
6. STOP 

### 5.3 Example Bus Transactions

#### Read seconds register (`0x02`)

* START
* `0xA2`
* `0x02`
* REPEATED START
* `0xA3`
* read 1 byte
* NACK
* STOP

#### Write time registers starting at seconds

* START
* `0xA2`
* `0x02`
* seconds byte
* minutes byte
* hours byte
* day byte
* weekday byte
* month/century byte
* year byte
* STOP

#### Enable 1 Hz CLKOUT

* START
* `0xA2`
* `0x0D`
* `0b10000011` = `0x83`
* STOP

## 7. Register Bitfields

### 7.1 Control/Status Register 1 (`0x00`)

| Bits | Name     | Access | Reset | Description                                                                                                                                      |
| ---- | -------- | ------ | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 7    | TEST1    | R/W    | 0     | `0`: normal mode; `1`: EXT_CLK test mode                                                                                                         |
| 6    | Reserved | R/W    | 0     | Must be 0                                                                                                                                        |
| 5    | STOP     | R/W    | 0     | `0`: RTC clock runs; `1`: all RTC divider stages asynchronously forced to 0 and RTC clock stops; CLKOUT remains available when set to 32.768 kHz |
| 4    | Reserved | R/W    | 0     | Must be 0                                                                                                                                        |
| 3    | TESTC    | R/W    | 1     | `0`: power-on reset function disabled in normal mode; `1`: power-on reset function enabled                                                       |
| 2:0  | Reserved | R/W    | 0     | Must be 0                                                                                                                                        |



### 7.2 Control/Status Register 2 (`0x01`)

| Bits | Name     | Access     | Reset         | Description                                                                                                                                                      |
| ---- | -------- | ---------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7:5  | Reserved | R/W        | 0             | Must be 0                                                                                                                                                        |
| 4    | TI_TP    | R/W        | 0             | `0`: INT active when TF valid, subject to TIE; `1`: INT pulse mode for timer, see timer pulse table; if AF and AIE are active simultaneously, INT remains active |
| 3    | AF       | R/WC-style | 0             | Alarm flag. Read `1` when alarm occurred. Writing `0` clears. Writing `1` leaves unchanged                                                                       |
| 2    | TF       | R/WC-style | 1 after reset | Timer flag. Read `1` when countdown ended. Writing `0` clears. Writing `1` leaves unchanged                                                                      |
| 1    | AIE      | R/W        | 0             | Alarm interrupt enable                                                                                                                                           |
| 0    | TIE      | R/W        | 0             | Timer interrupt enable                                                                                                                                           |

Important write semantics:

* `AF=0` on write clears AF.
* `AF=1` on write preserves current AF.
* `TF=0` on write clears TF.
* `TF=1` on write preserves current TF.

Therefore writes that clear flags must use a read-modify-write logical AND style update to avoid unintentionally reasserting a flag.

| ---- | ----------- | ------ | ----- | -------------------------------- |
| 7:0  | Timer Value | R/W    | 0     | 8-bit binary countdown value `n` |

Countdown period:

`period = n / timer_clock_frequency`

When `n = 0`, the timer stops.  

## 8. Reserved Bit Handling

Reserved or invalid bits appear throughout the register set. Required handling:

* Bits marked `0` in the register summary must be written as logic 0.
* Bits marked invalid or unused must not be relied upon when read.
* Firmware should preserve only defined writable fields and force reserved bits to 0 on writes.
* For flag registers using clear-on-write-zero semantics, write only the intended defined bits and keep reserved bits 0.

This rule is explicitly stated for the register summary: bits marked `0` shall be set to logic 0. 

## 9. Commands or Opcodes

BM8563 does not define a separate opcode command protocol. All host interaction is register-based over I2C. The effective “commands” are register reads and writes.

## 10. Data Formats

### 10.1 Time and Calendar Encoding

The following registers use BCD encoding:

* Seconds `0x02`
* Minutes `0x03`
* Hours `0x04`
* Day `0x05`
* Month `0x07`
* Year `0x08`
* Minute alarm `0x09`
* Hour alarm `0x0A`
* Day alarm `0x0B`

The following are not BCD:

* Weekday `0x06`: binary `0..6`
* Weekday alarm `0x0C`: binary `0..6`
* Timer value `0x0F`: binary `0..255` 

### 10.2 Century Representation

* `C=0` => years 20XX
* `C=1` => years 19XX

When the year rolls from `99` to `00`, the century bit changes. 

### 10.3 Power-Loss Indicator

* `VL=0`: no power-loss indication
* `VL=1`: power-loss indicated

Application software may mask this bit when displaying seconds. 

### 10.4 Timer Period Formula

For timer count `n` and timer source clock `f_timer`:

`countdown_period_seconds = n / f_timer`

Where `f_timer` is one of `4096`, `64`, `1`, or `1/60`. 

## 11. Timing Requirements

### 11.1 I2C Bus Timing

* fSCL max: 400 kHz
* tHD;STA min: 0.6 µs
* tSU;STA min: 0.6 µs
* tLOW min: 1.3 µs
* tHIGH min: 0.6 µs
* tr max: 0.3 µs
* tf max: 0.3 µs
* tSU;DAT min: 100 ns
* tHD;DAT min: 0 ns
* tSU;STO min: 0.6 µs
* tSW max: 50 ns
* Cb max: 400 pF
* Total access duration between two START conditions and one STOP must be < 1 s 

### 11.2 Oscillator Parameters

* Oscillator frequency: 32.768 kHz
* Internal single-sided load capacitance CINT: 6 pF typical
* External trim capacitor per side CT: 6 pF to 22 pF
* Crystal ESR: 30 kΩ typical, 50 kΩ max
* Crystal load capacitance CL: 6 pF typical, 12.5 pF max
* Oscillator stability with ΔVDD = 200 mV at TA = 25 °C: `2 × 10^-7` typical  

### 11.3 CLKOUT Timing

* CLKOUT duty cycle: 50% typical at 32.768 kHz unless otherwise stated 

### 11.4 Reset / POR Defeat Timing

To enter POR defeat mode, the SDA and SCL waveform must satisfy the minimum pattern shown in the source figure:

* A timing segment labeled `> 500 ns`
* A timing segment labeled `> 2000 ns`
* Delay from power-up labeled approximately `8 ms`

Because the exact pulse sequence is only provided graphically, firmware should avoid this mode unless specifically required for test. 

### 11.5 Timer Read Accuracy Constraint

To read back an accurate current countdown value, I2C SCL frequency should be at least twice the selected timer clock frequency. Therefore:

* If timer clock = 4096 Hz, use SCL ≥ 8192 Hz
* If timer clock = 64 Hz, use SCL ≥ 128 Hz
* If timer clock = 1 Hz, use SCL ≥ 2 Hz
* If timer clock = 1/60 Hz, use SCL ≥ 1/30 Hz 

## 12. Operating Modes

### 12.1 Normal Mode

* `TEST1=0`
* RTC runs if `STOP=0`
* Normal timekeeping, alarm, timer, and CLKOUT available 

### 12.2 RTC Stopped Mode

* `STOP=1`
* All RTC divider stages asynchronously set to 0
* RTC clock stops
* CLKOUT at 32.768 kHz remains available 

### 12.3 EXT_CLK Test Mode

* `TEST1=1`
* Test mode, not for normal firmware use 

### 12.4 Timer Disabled / Enabled

* Controlled by `TE`
* Timer source selected by `TD1:TD0`
* Timer interrupt behavior selected by `TI_TP`, `TIE`, and `TF`  

### 12.5 Alarm Enabled / Disabled

Each alarm field has an `AE` bit:

* `AE=0`: corresponding field participates in match
* `AE=1`: corresponding field ignored

Alarm may be configured for matching one or more of minute, hour, day, weekday. Depending on enabled fields, the alarm may repeat from once per minute up to once per week.  

## 13. Reset Behavior

BM8563 includes an internal reset circuit. When the oscillator stops, reset begins. During reset:

* I2C bus is initialized
* address pointer is reset
* all registers are cleared to 0 except:

  * `TF = 1`
  * `VL = 1`
  * `TD1 = 1`
  * `TD0 = 1`
  * `TESTC = 1`
  * all `AE` bits = 1 

Implications:

* Alarm registers default to disabled because AE bits reset high
* Timer source defaults to 1/60 Hz because `TD1:TD0 = 11`
* Power-loss indication defaults asserted
* Timer flag defaults asserted
* TESTC defaults enabled

## 14. Status and Diagnostics

### 14.1 Voltage-Low / Power-Loss Status

* `VL` in register `0x02`, bit 7
* Indicates power-loss condition
* Software should inspect this after startup or time read to determine whether RTC contents may be invalid 

### 14.2 Alarm Status

* `AF` in register `0x01`, bit 3
* Set when alarm occurs
* Remains set until software clears it
* Used to identify alarm interrupt source when timer and alarm share INT 

### 14.3 Timer Status

* `TF` in register `0x01`, bit 2
* Set when countdown reaches terminal event
* Remains set until software clears it
* Used to identify timer interrupt source when timer and alarm share INT 

## 15. Interrupts

### 15.1 INT Pin

* Open-drain output
* Alarm and timer share the interrupt path
* Requires external pull-up 

### 15.2 Interrupt Enables

* `AIE`: alarm interrupt enable
* `TIE`: timer interrupt enable

When both are enabled, INT is the logical OR of the enabled sources. 

### 15.3 Alarm Interrupt Source

Triggered when enabled alarm fields match current time/date and `AIE=1`. `AF` latches high until software clears it.  

### 15.4 Timer Interrupt Source

Triggered when countdown timer terminal event occurs and `TIE=1`. `TF` latches high until software clears it. Timer pulse behavior depends on `TI_TP`.  

### 15.5 Timer Pulse Mode (`TI_TP=1`)

INT pulse period by timer clock:

| Timer Clock | INT period when n=1 | INT period when n>1 |
| ----------- | ------------------- | ------------------- |
| 4096 Hz     | 1/8192 s            | 1/4096 s            |
| 64 Hz       | 1/128 s             | 1/64 s              |
| 1 Hz        | 1/64 s              | 1/64 s              |
| 1/60 Hz     | 1/64 s              | 1/64 s              |

If `AF` and `AIE` are active simultaneously, INT stays active. 

### 15.6 Clearing Behavior

* Clear AF by writing AF bit to 0
* Clear TF by writing TF bit to 0
* Use read-modify-write to avoid overwriting the other flag or enabled bits 

## 16. Operational Sequences

### 16.1 Set Time and Date

1. Optionally set `STOP=1` to halt RTC divider chain.
2. Write registers `0x02` through `0x08` with BCD-encoded seconds, minutes, hours, day, weekday, month/century, year.
3. Clear `VL` handling at application layer by acknowledging prior power-loss state.
4. Set `STOP=0` to start RTC if previously stopped.

### 16.2 Read Time and Date

1. Perform sequential read from `0x02` through `0x08`.
2. Decode BCD fields.
3. Check `VL`; if set, treat returned time as potentially invalid.
4. Convert `C` + year to full year.

### 16.3 Configure Alarm

1. Program enabled alarm fields at `0x09..0x0C` with `AE=0`.
2. Program ignored alarm fields with `AE=1`.
3. Clear `AF`.
4. Set `AIE=1` if interrupt-driven alarm handling is needed.

### 16.4 Configure Timer

1. Write timer source in `0x0E[1:0]`.
2. Write countdown value `n` to `0x0F`.
3. Clear `TF`.
4. Set `TIE` and `TI_TP` as needed in `0x01`.
5. Set `TE=1` in `0x0E`.

### 16.5 Configure CLKOUT

1. Program `FD1:FD0` in `0x0D`.
2. Set `FE=1` to enable or `FE=0` to disable.

## 17. Driver Initialization Sequence

Recommended startup sequence:

1. Probe I2C address `0x51`.
2. Read `0x00`, `0x01`, and `0x02`.
3. Force normal mode:

   * `TEST1=0`
   * reserved bits = 0
4. Decide whether to keep or clear `TESTC`; for standard operation, keep it under explicit control and do not enter test mode.
5. Clear stale flags:

   * clear `AF`
   * clear `TF`
6. Check `VL`:

   * if `VL=1`, mark RTC time invalid and require host time initialization
7. Set timer source to `TD1:TD0=11` and `TE=0` if timer is unused
8. Disable `CLKOUT` unless needed
9. Disable interrupts or configure them explicitly
10. If time must be initialized, write `0x02..0x08`
11. Ensure `STOP=0`

## 18. Runtime Operation Sequences

### 18.1 Reading Current Time

* Sequential read `0x02..0x08`
* Decode BCD
* Validate ranges
* Inspect `VL`

### 18.2 Updating Time

* Optional `STOP=1`
* Burst-write `0x02..0x08`
* `STOP=0`

### 18.3 Handling Interrupt

1. Read `0x01`
2. If `AF=1`, process alarm event
3. If `TF=1`, process timer event
4. Clear the relevant flag bits with read-modify-write
5. Return to idle

### 18.4 Updating Alarm

1. Disable `AIE` if avoiding transient interrupt behavior
2. Write `0x09..0x0C`
3. Clear `AF`
4. Re-enable `AIE`

### 18.5 Updating Timer

1. Disable timer `TE=0`
2. Write new timer source if needed
3. Write new count to `0x0F`
4. Clear `TF`
5. Re-enable timer if needed

## 19. Driver State Model

A correct driver should track:

* I2C bus address `0x51`
* Whether RTC contents are valid based on `VL`
* Whether timer is configured and enabled
* Timer source frequency
* Alarm configuration and enabled match fields
* Interrupt enable state (`AIE`, `TIE`)
* CLKOUT enable and selected frequency
* Optional cached copy of control/status registers for safe read-modify-write handling
* Full-year interpretation policy using `C` + `YY`

## 20. Required Safety and Correctness Rules for Code Generation

1. Always write reserved bits as 0.
2. Treat `0x51` as the 7-bit I2C address; use `0xA2`/`0xA3` only as transferred address bytes.
3. Use BCD conversion for all BCD-coded fields.
4. Do not apply BCD conversion to weekday or timer value.
5. Check `VL` before trusting RTC contents.
6. Use read-modify-write when clearing `AF` or `TF`.
7. Do not assume `TF=0` after reset; it resets to 1.
8. Do not assume alarms are enabled after reset; `AE` bits reset to 1, disabling all alarm fields.
9. When timer is unused, set `TD1:TD0=11` to reduce power.
10. If accurate current timer value is required, ensure SCL frequency is at least 2× timer source frequency.
11. Keep `TEST1=0` in production firmware.
12. Avoid POR defeat and EXT_CLK test mode in normal operation.
13. Validate time field ranges before writing:

    * seconds `00..59`
    * minutes `00..59`
    * hours `00..23`
    * day `01..31`
    * weekday `0..6`
    * month `01..12`
    * year `00..99`
14. Validate alarm ranges using the same logic as the corresponding time fields.
15. Decode century with `C=0 => 20XX`, `C=1 => 19XX`.
16. INT and CLKOUT are open-drain; board support must provide pull-ups as required.
17. Keep total I2C access time from START to STOP under 1 s.

## 24. Minimal Functional Feature Set

A minimally correct driver must implement:

* I2C probe at address `0x51`
* Register read and write
* Sequential multi-byte read/write
* BCD encode/decode helpers
* Read current time/date
* Set current time/date
* Check and report `VL`
* Configure and clear alarm
* Configure and clear timer
* Control `AIE`, `TIE`, `AF`, `TF`
* Configure `CLKOUT`
* Preserve reserved-bit requirements

## 25. Final Implementation Intent

A generated driver should expose a stable software interface for RTC timekeeping, alarm scheduling, countdown timing, and optional clock output while honoring all bus timing, bitfield semantics, reset defaults, and open-drain interrupt behavior defined above.

Common implementation mistakes to avoid:

* using `0xA2` as the 7-bit address instead of `0x51`
* treating weekday as BCD
* ignoring `VL`
* writing reserved bits as 1
* clearing `AF`/`TF` incorrectly without read-modify-write
* assuming timer flag resets cleared
* enabling alarm fields without clearing `AE`
* writing invalid BCD values
* forgetting that `CLKOUT` and `INT` are open-drain
* using hour/day/weekday alarm ranges from obvious table typos instead of the corresponding logical register formats

## Appendix A: Electrical and Integration Constraints

### Supply and Current

* VDD: `1.5..5.5 V` with I2C inactive (TA = 25 °C)
* VDD: `1.8..5.5 V` with I2C active at 400 kHz
* Reliable clock/calendar data voltage at TA=25 °C: `Vlow .. 5.5 V` (the
  minimum `Vlow` is not numerically specified in the datasheet table)
* Active current with CLKOUT enabled (FE=1), max:

  * fSCL = 400 kHz: 800 µA
  * fSCL = 100 kHz: 200 µA
* Sleep current with CLKOUT disabled (FE=0), fSCL=0 Hz, TA=25 °C:

  * 5.0 V: typ 550 nA, max 800 nA
  * 3.0 V: typ 250 nA, max 650 nA
  * 2.0 V: typ 200 nA, max 500 nA
* Sleep current with CLKOUT = 32.768 kHz (FE=1), fSCL=0 Hz, TA=25 °C:

  * 5.0 V: typ 900 nA, max 1600 nA
  * 3.0 V: typ 650 nA, max 1000 nA
  * 2.0 V: typ 525 nA, max 800 nA
* Higher-current values apply over the full −40..+85 °C range and may be
  used for power modeling.

### Crystal Selection

Recommended crystal and matching:

* Frequency: 32.768 kHz
* Load capacitance CL: 6 pF recommended, 12.5 pF maximum listed
* ESR: less than 50 kΩ recommended
* For a 6 pF crystal, connect approximately 6 pF matching capacitors at OSCI and OSCO
* For a 12.5 pF crystal, connect approximately 19 pF matching capacitors at OSCI and OSCO
* If VCC contains noise/interference, add RC filtering on the supply line
