# ILI9342C LCD Controller Reference

Source: `ILI9342C.pdf`, ILITEK ILI9342C specification V1.01.

## Device Overview

**ILI9342C** is a single-chip TFT LCD driver supporting:

* **Resolution:** 320 × 240 pixels (RGB subpixel addressing)
* **Color depth:** up to **262,144 colors**
* **Integrated GRAM:** 172,800 bytes
* **Source outputs:** 960
* **Gate outputs:** 240
* **Interfaces supported**

  * MCU parallel: 8-bit, 9-bit, 16-bit, 18-bit
  * Serial: 3-wire SPI, 4-wire SPI
  * RGB interface: 6-bit, 16-bit, 18-bit

The device contains:

* Internal display RAM (GRAM)
* Timing generator
* Oscillator
* Charge pump power system
* VCOM generator
* Backlight PWM controller
* Gamma correction circuitry
* Dynamic backlight control

The display driver supports:

* Full color mode (262K colors)
* Reduced color mode (8 colors)
* Sleep mode
* Partial update regions
* Vertical scrolling
* Frame synchronization via tearing signal

# Extended Command Set Enable (EXTC)

Level 2 (extended) commands in the range **B0h–FFh** are gated behind an EXTC
unlock. They are treated as NOP unless EXTC has been enabled.

To enable the extended command set, write **Set EXTC (C8h)** with the three
parameters:

```
C8h  -> 0xFF, 0x93, 0x42
```

Most level 2 command descriptions in the datasheet are annotated
"Set EXTC(C8h)=FF,93,42 to enable this command." A driver MUST send this
sequence during initialization before issuing any B0h–FFh configuration
commands (frame rate, power, VCOM, gamma, interface control, etc.). Undefined
commands are treated as NOP (00h).

# Memory Access Control (36h)

Controls display orientation and color order. Takes **one parameter byte**.
Default (power-on / hardware reset) value is **0x00**. Software reset does not
change MADCTL.

Parameter byte bit layout (`MY MX MV ML BGR MH 0 0`):

| Bit | Name | Function                 | `0`                       | `1`                       |
| --- | ---- | ------------------------ | ------------------------- | ------------------------- |
| D7  | MY   | Row address order        | Top to Bottom             | Bottom to Top             |
| D6  | MX   | Column address order     | Left to Right             | Right to Left             |
| D5  | MV   | Row/column exchange      | Normal                    | Row/Column exchanged      |
| D4  | ML   | Vertical refresh order   | LCD refresh Top to Bottom | LCD refresh Bottom to Top |
| D3  | BGR  | RGB-BGR color order      | RGB color filter          | BGR color filter          |
| D2  | MH   | Horizontal refresh order | LCD refresh Left to Right | LCD refresh Right to Left |
| D1  | —    | Reserved                 | Set to `0`                | —                         |
| D0  | —    | Reserved                 | Set to `0`                | —                         |

Note: When the `BGR` bit is changed, the new color order is applied immediately
without rewriting GRAM. `MY/MX/MV` control the MCU-to-memory write/read scan
direction; data is always written to frame memory in the same physical order.

---

# Pixel Format Set (3Ah)

Defines pixel format for the host interface. Takes **one parameter byte** with
the structure `0 DPI[2:0] 0 DBI[2:0]`:

* `DPI[2:0]` — RGB (display) interface pixel format
* `DBI[2:0]` — MCU (host) interface pixel format

Per-field encoding:

| `DPI`/`DBI` | Format        |
| ----------- | ------------- |
| `101`       | 16 bits/pixel |
| `110`       | 18 bits/pixel |
| others      | Reserved      |

Common full-byte parameter values:

| Value | DPI / DBI        | Format                  |
| ----- | ---------------- | ----------------------- |
| 55h   | `101` / `101`    | 16-bit/pixel (RGB565)   |
| 66h   | `110` / `110`    | 18-bit/pixel (RGB666)   |

Default (power-on / hardware reset): **0x66** (18 bits/pixel). Software reset
does not change the pixel format. When using the RGB interface, the serial
interface must be selected for register access.

# Identification and Read Return Values

Read commands return fixed identification and status data. The first byte
clocked out of any read command is a dummy byte (discard it). Default values
below are the power-on / hardware reset state.

| Command | Code | Bytes | Default value     | Meaning                                           |
| ------- | ---- | ----- | ----------------- | ------------------------------------------------- |
| RDDID   | 04h  | 3     | `E3 00 00`        | ID1=manufacturer (`E3`), ID2, ID3                 |
| RDDST   | 09h  | 4     | `00 61 00 00`     | Display status                                    |
| RDDPM   | 0Ah  | 1     | `08`              | Power mode                                        |
| RDDMADCTL | 0Bh | 1    | `00`              | Current MADCTL value                              |
| RDDCOLMOD | 0Ch | 1    | `06`              | Current pixel format (DPI/DBI)                    |
| RDDIM   | 0Dh  | 1     | `00`              | Image mode                                        |
| RDDSM   | 0Eh  | 1     | `00`              | Signal mode                                       |
| RDDSDR  | 0Fh  | 1     | `00`              | Self-diagnostic result                            |
| RDID1   | DAh  | 1     | `E3`              | Manufacturer ID (LCD module supplier)             |
| RDID2   | DBh  | 1     | `00`              | Module/driver version ID                          |
| RDID3   | DCh  | 1     | `00`              | Module/driver ID                                  |
| RDID4   | D3h  | 3     | `00 93 42`        | IC device code = **0x9342** (use to detect part)  |

Driver tip: Read ID4 (D3h) is the most reliable way to confirm an ILI9342C is
present; the returned 16-bit device code is `0x9342`.

# Initialization Command Parameter Reference

Parameter formats for the commands typically needed in an init sequence. All
multi-byte coordinate values are big-endian (high byte first). Level 2 commands
require EXTC enabled (see Set EXTC C8h above).

## Column Address Set (2Ah) — 4 params

```
SC[15:8], SC[7:0], EC[15:8], EC[7:0]   ; 0 <= SC <= EC <= 319
```

## Page Address Set (2Bh) — 4 params

```
SP[15:8], SP[7:0], EP[15:8], EP[7:0]   ; 0 <= SP <= EP <= 239
```

## RGB Interface Signal Control (B0h) — 1 param

```
ByPass_MODE RCM1 RCM0 0 VSPL HSPL DPL EPL   ; default 0x40
```

* `RCM[1:0]`: `10` = DE mode (use DE signal), `11` = SYNC mode (use VSYNC/HSYNC)
* `VSPL/HSPL/DPL/EPL`: VSYNC / HSYNC / DOTCLK / DE signal polarity

## Frame Rate Control – Normal Mode (B1h) — 2 params

```
0 0 0 0 0 0 DIVA[1:0]   ; param1, internal clock division (default 0x00)
0 0 0 RTNA[4:0]         ; param2, clocks per line (default 0x1C)
```

`DIVA` selects fosc/1, /2, /4, /8. `RTNA` sets line period; default `0x00, 0x1C`
≈ 70 Hz frame rate.

## Display Inversion Control (B4h) — 1 param

```
0 0 0 0 0 NLA NLB NLC   ; inversion mode, default 0x00 (column inversion 2-dot)
```

## Display Function Control (B6h) — 4 params

```
0 0 0 0 0 0 PTG[1:0]            ; param1, default 0x0A
REV GS SS SM ISC[3:0]          ; param2, default 0x82
0 0 NL[5:0]                    ; param3, number of lines (default 0x27 = 320? for 240-line panel set per module)
0 0 PCDIV[5:0]                 ; param4 (optional)
```

## Power Control 1 (C0h) — 2 params

```
0 0 0 VRH1[4:0]   ; param1, default 0x09 (GVDD level)
0 0 0 VRH2[4:0]   ; param2, default 0x09
```

## Power Control 2 (C1h) — 1 param

```
0 BT[2:0] 0 VC[2:0]   ; step-up factor / reference, default 0x00
```

## VCOM Control 1 (C5h) — 2 params

```
nVM VCM[6:0]   ; param1, VCOMH/VCOML level, default 0xF2
... VML[6:0]   ; param2 (where applicable)
```

## Positive / Negative Gamma Correction (E0h / E1h) — 15 params each

Each command takes **15 parameters** (VP/VN gamma adjustment points). E0h sets
the positive polarity curve, E1h the negative polarity curve. The two curves
should be symmetric for correct grayscale.

## Interface Control (F6h) — 3 params

```
MY_EOR MX_EOR MV_EOR 0 0 BGR_EOR 0 WEMODE     ; param1
0 0 EPF[1:0] 0 0 MDT[1:0]                      ; param2
0 0 ENDIAN 0 DM[1:0] RM RIM                    ; param3
```

* `WEMODE`: GRAM data wrap behavior on overflow
* `EPF[1:0]`: 16-bit to 18-bit pixel expansion mode
* `ENDIAN`: host data endianness (serial interface only)
* `RM`/`DM[1:0]`: RAM access / display operation interface select
* `RIM`: RGB interface bus width

# Reset and Sleep Timing

Mandatory delays a driver must honor.

| Event                              | Constraint                                         |
| ---------------------------------- | -------------------------------------------------- |
| RESX low pulse width               | >= 10 us                                           |
| Reset (display in Sleep Out)       | Wait 120 ms after RESX rising before next command  |
| Reset (display in Sleep In)        | Wait 5 ms after RESX rising before next command    |
| Software Reset (01h)               | Wait 5 ms before next command                      |
| Sleep Out (11h)                    | Wait 120 ms before sending Sleep In; 5 ms before any other command |
| Sleep In (10h)                     | Wait 120 ms after Sleep Out before issuing Sleep In; 5 ms settle    |

Typical init order: hardware reset -> wait -> SWRESET (01h) -> 5 ms -> Set EXTC
(C8h FF 93 42) -> power/VCOM/frame/gamma config -> MADCTL (36h) -> COLMOD (3Ah)
-> Sleep Out (11h) -> 120 ms -> Display ON (29h).

# RGB Interface Configuration

When driven over the RGB (DPI) interface, blanking and polarity are configured
with these commands (level 2, EXTC required):

| Command                | Code | Default params | Purpose                            |
| ---------------------- | ---- | -------------- | ---------------------------------- |
| RGB Interface Control  | B0h  | `40`           | RCM mode (DE vs SYNC) and polarity |
| Blanking Porch Control | B5h  | `02 02 0A 14`  | VFP, VBP, HFP, HBP                 |

Blanking Porch Control (B5h) parameters: Vertical Front Porch, Vertical Back
Porch, Horizontal Front Porch, Horizontal Back Porch (in lines/clocks).
